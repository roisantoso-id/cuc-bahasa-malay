
## 新加坡服务器加固（2026-11-18）

照广州机的做法重做了一遍，体检脚本（全局 skill `sec-server` 的 `server-audit.sh`）从 3 个 FAIL 变成 0 个 FAIL。

- **SSH**：`/etc/ssh/sshd_config.d/00-jombelajar-hardening.conf`，只允许 `ubuntu` 用密钥登录，禁止密码、键盘交互和 root 登录，最多试 3 次，LoginGraceTime 20，关 X11。文件名用 `00-` 开头，压过云镜像自带的 `50-cloud-init.conf`。
- **fail2ban**：`/etc/fail2ban/jail.d/jombelajar.local`，SSH 10 分钟内失败 5 次封 1 小时，再犯翻倍，最长 1 周。Ubuntu 24.04 的 SSH 服务名是 `ssh.service`，fail2ban 默认按 `sshd.service` 读日志，什么都抓不到。所以 jail 里写了 `journalmatch = _SYSTEMD_UNIT=ssh.service + _COMM=sshd`。
- **防火墙 ufw**：默认拒绝入站，22 用 `limit`（30 秒内超过 6 次新连接就拒），只放行 80、443，IPv6 同样生效。Docker 只发布了 web 的 80/443，api 的 4200 只在 Docker 内网，没有绕过 ufw 的端口。腾讯主机安全自带的 `YJ-FIREWALL-INPUT` 链没动。
- **本机 SSH 复用连接**：因为 22 有 `limit`，部署脚本连续开 6 个以上连接会被拒。Mac 上 `~/.ssh/config` 的 `jombelajar` 别名已加 `ControlMaster auto` / `ControlPersist 10m`，部署一律用这个别名，不要直接写 IP。
- **内核网络参数**：`/etc/sysctl.d/90-jombelajar.conf`，内容和广州机一样：SYN cookies、反向路径过滤、禁止 ICMP 重定向和源路由、记录异常包、限制 kptr / dmesg、保护软硬链接。`ip_forward` 保持 1，Docker 要用。镜像的 `/etc/sysctl.conf` 写了 `kernel.sysrq = 1`，而且最后加载，已改成 0。原文件备份在 `/etc/sysctl.conf.bak-20261118`。
- **自动安全更新**：镜像把 `50unattended-upgrades` 里 `-security` 那一行注释掉了，等于什么都不装，已打开。原文件备份在 `/root/50unattended-upgrades.bak-20261118`。积压的 165 个更新已手动装完，包括新内核 6.8.0-149。
- **删掉没用的软件**：`inetutils-telnetd`、`inetutils-inetd`（镜像自带，没在跑）。
- **检查过**：加固后 www / admin 返回 200，`api.bahasa.cn/api/admin/students` 返回 401（api 根路径和后台是同一套服务，本来就返回 200）。新窗口用密钥能登录，api 容器能连到 MySQL 10.3.4.2:3306 和外网。

还要做（用户自己）：

- **重启**：新内核和 libc6 要重启才生效。两个容器都是 `unless-stopped`，docker / fail2ban / ufw 都设了开机启动，挑没人用的时候 `sudo reboot`，重启后再看三个网址。
- **轻量服务器控制台防火墙**：入站只留 TCP 22、80、443，其它都删掉。443/udp（HTTP/3）现在没发布，不用开。改完确认服务器还能连到内网的 MySQL 10.3.4.2:3306。
- **认清登录公钥**：`ubuntu` 有 3 把。`SHA256:Gp7jUrtq…` 没有备注，认不出是谁的，可能是控制台绑定的密钥。`SHA256:K41OhIul…` 是 qie-server（2026-11-13）的。`SHA256:AqZbdfyN…` 是这台 Mac 的。不认识的要删掉，控制台里也要解绑，否则重装系统会写回来。
- **腾讯云自动化助手 `tat_agent`** 在跑，能不经 SSH 用 root 执行命令。需要确认：主账号开了 MFA，主账号没有 AccessKey，所有子账号和 Key 都禁止「执行命令 / 传文件」，CloudAudit 对「执行命令」有告警。用不到就停掉。
